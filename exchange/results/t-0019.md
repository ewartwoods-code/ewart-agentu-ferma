**Where the data comes from — two sources, kept apart on purpose:**

1. **Curated facts** (`SYSTEM_MAP`). No provider exposes a "describe my ecosystem" read, so these
   rows are written by hand. Each node carries `id, name, kind, lane, logo_url, status,
   what_it_is, what_it_does, flow_in, flow_out, connects_to[], evidence` — the field list the task
   asked for, plus `evidence`, which is the field that keeps the map honest.
2. **The live `agents` table.** The specialists shown inside an AI platform come from
   `agents.parent_id` (the t-0015 hierarchy), never from the config. With the hierarchy migration
   unapplied the page's existing preview grouping is reused and the chip row says
   *"priekšskatījums — hierarhija vēl nav datubāzē"*.

**Five honesty decisions, each enforced by a test:**

1. **No node is green unless something measured it.** Every `status: 'active'` cites the read-only
   connector test in `exchange/results/t-0002.md` (2026-08-16) or a file in this repo. Klaviyo,
   Google Ads, Pinterest, Meta, GPT, Grok and ElevenLabs were never verified, so they are
   `pending` — the map says "gaida savienojumu", not "connected".
2. **Etsy is pending, twice.** The store node and a separate `Etsy / eRank konektors` node, whose
   whole description is *"tas savienojums, kura fermā vēl nav"*. That is the largest real hole in
   the farm's data flow and the map points at it rather than hiding it.
3. **PayPal is blocked, with the error quoted.** `"Failed to retrieve invoices: Unauthorized."` —
   one node in red is more useful than 26 in green.
4. **The store -> database ingest arrow is dashed and labelled `(plāns)`.** The task asked for
   `stores -> ingest -> Supabase -> app`. That pipeline **does not exist in this repo**: store data
   is read live through MCP connectors inside a Claude session and lands in `exchange/` reports,
   not in Supabase. Drawing it solid would have been the single biggest lie available on this
   screen. It is dashed, the legend explains dashed, the words `(plāns)` are in the chip, and the
   footnote repeats it. The three flows that *do* work are solid.
5. **The footnote counts the map instead of implying it all works:**
   `26 punkti — savienoti: 15, gaida savienojumu: 10, bloķēti: 1.`

**Logos.** Every logo is the brand's **own** favicon (`https://www.etsy.com/favicon.ico`,
`https://openai.com/favicon.ico`, …) — never a third-party logo proxy such as
`google.com/s2/favicons`, which would route a farm visit through a third party. 20 of 26 nodes
have one; the 6 internal ones (Saimnieks, Hermes, lietotne, exchange, Mac, Etsy konektors) have no
brand and show a letter. Behind **every** logo sits a monogram drawn by CSS
(`.node-logo::before{ content:attr(data-monogram) }`); a logo that fails to load is hidden by the
error handler, uncovering the letter. So the map cannot render a broken image even offline.

While doing that I fixed a latent defect in the shared `initialsFor()` (`:1346-1354`): it took the
first character of the first two whitespace-separated words, so *"Herme — Galvenais Fermeris"*
produced the monogram `H—`. It now skips words that do not start with a letter or digit (`HG`,
and `M` for *"Meta (Facebook / Instagram)"*). That helper is also the field-character and platform
badge fallback, so the fix lands in three places at once.

### 2. Deliverable 2 — no new table, and why

The task said a `connections` / `system_map` table **only if needed**. It is not needed, so I did
not add one. A migration cannot be applied under `code_local`, so a table-backed map would render
empty on the live site and the owner would see nothing at all. The config object ships with the
page, renders instantly, and needs no migration; it is one array to extend. If Hermes later wants
the owner to edit the map from the control panel, that is a table **plus** a token-gated
`admin_upsert_map_node` RPC — a separate task, and worth doing only then.

### 3. Tests — `scripts/test-system-map.js` (new, 38 checks), `scripts/dump-system-map.js` (new tool), `scripts/verify-app-endpoints.js` (+1)

Same harness as t-0015/t-0016/t-0018: the shipped `<script>` block is extracted from `index.html`
and evaluated against a DOM stub, so the checks drive the **real** `renderSystemMap()` /
`openNodeInfo()`, not a copy. `fetch` throws unless a fixture is installed, and a counter proves
nothing reached the network.
