### 3. Built the automation (deliverable 3)

```
  1. EXTRACT                2. NORMALISE            3. LOAD              4. SCHEDULE
  Seller Labs / SP-API  ->  amazon-ingest.js   ->   psql upsert     ->   daily, D-1
  NOT BUILT                 BUILT + TESTED          BUILT (emits);       NOT BUILT
  (needs a connector        (54 offline checks)     applying needs a     (server-side)
  this node may not use)                            write credential
```

`scripts/amazon-ingest.js` (dependency-free CommonJS, no network, no database,
no Amazon call) reads every raw envelope for a business day out of
`data/amazon-raw/`, merges them into one canonical row per marketplace, and
emits an idempotent upsert. Six rules, each with a test:

1. **Unmeasured stays `null`, never 0**, and the report names every field nobody
   measured. A `0` a source reported is kept as a measured zero. Same rule as
   `scripts/platform-scorecards.js` and `scripts/shipping-cost-engine.js`.
2. **Ad-attributed numbers never become totals.** An ads report's `orders` and
   `sales` land in `ad_orders` / `ad_sales`. This is the most valuable rule in
   the file: t-0036 established that the farm's entire visible Amazon revenue
   figure (€3,787.34 / 30d) is ad-attributed only, and merging the two would
   permanently destroy the difference between "sold" and "sold by an ad".
3. **Currencies are never converted or summed** — the account spans EUR, GBP and
   SEK, and a marketplace reporting two currencies for one day is a hard error.
4. **Two sources that disagree stop the run**, rather than last-writer-wins.
5. **A day with no extract exits 2 and writes nothing.** A visible gap beats a
   row of zeros that reads like a catastrophic sales day.
6. **The upsert is idempotent**: `x = coalesce(excluded.x, metrics.x)`, so
   re-running the ads extract can never blank an already-loaded orders value.

Because nobody in this workspace has read the real `metrics` DDL,
`data/amazon-ingest-target.json` declares the column mapping with
`"verified": false` and the generator **refuses to emit SQL** unless forced —
and then stamps an `UNVERIFIED TARGET SCHEMA` banner into the file.
