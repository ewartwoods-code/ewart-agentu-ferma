## 2. Autopilot script — BUILT AND TESTED

`scripts/autopilot.sh` (executable, syntax-checked with `bash -n`). It does, in order:

1. `cd` to the repo and `git pull --quiet origin master` — no force, no reset. On failure it logs and exits 1.
2. Finds the **lowest-numbered** file in `exchange/tasks/` whose `t-NNNN` has no `exchange/results/t-NNNN.md`. None → logs `no tasks`, exits 0.
3. **Transport-only mode (default):** logs the detected task and exits 0 without running anything.
4. **Execute mode:** resolves the binary via `command -v claude`, falling back to `~/.local/bin/claude`; if absent, logs and exits 1.
5. Runs the task headless with `--max-turns 60` and a scoped `--allowedTools` list, with a prompt that repeats the money/publish prohibition.
6. `git add -A`, commits as `t-NNNN autopilot: <title>`, pushes. **If the push is refused it logs and exits 1 — no bypass, no retry loop.**
7. Appends `<ISO-8601> | t-NNNN | exit <code> | <note>` to `state/log-mac.md`.

Mode is controlled by `AUTOPILOT_EXECUTE` (`0` default, `1` to execute).

## 5. The one deviation, and why

The task specified:

```
claude -p --dangerously-skip-permissions --max-turns 60 "..."
```

The script uses a scoped `--allowedTools` list instead. This is deliberate, and it is the only place where the implementation departs from the spec.

**The flag contradicts the task's own constraint.** t-0007 §Constraints says the autopilot "must not apply money/publish actions" and that `needs_review` items "stop for owner approval". `--dangerously-skip-permissions` disables every permission gate in the process, which turns that constraint into a sentence in a prompt with nothing enforcing it. A task file that said "pause these campaigns" or "send this email" would simply be carried out, unattended, within fifteen minutes. Both cannot be true; the script keeps the constraint and drops the flag.

**The blast radius is the reason it matters here.** Instructions arrive by `git pull` from a GitHub repo. Whoever can push to that repo decides what runs on this Mac. Claude sessions on this machine can reach Shopify, Amazon Ads across 12 marketplaces with live budget, Gmail, Drive, Calendar, Asana, Supabase, Railway and a payments connector. An unattended 15-minute loop with all gates off is a remote-execution path into all of it, and the owner — non-technical, and not at the keyboard by design — would be the last to know.

This is not a refusal of the autopilot. The transport loop is built, tested and ready. It is a refusal to install the specific mechanism that removes human review, without the owner understanding that is what he is turning on. If Hermes and the owner want it after reading this, it is a one-line change in `scripts/autopilot.sh`, documented in `scripts/AUTOPILOT-SAFETY.md`.

A middle option worth considering: keep `--allowedTools` scoped as it is now. Analysis tasks like t-0003 and t-0006 — the actual work so far — need only file writes, SQL reads and read-only API calls. They would run unattended perfectly well. Only the money-moving actions would stop and wait, which is the stated design.

## How to turn it off — for the owner

```
launchctl unload ~/Library/LaunchAgents/com.ewartwoods.farm-autopilot.plist
rm ~/Library/LaunchAgents/com.ewartwoods.farm-autopilot.plist
```

That is the entire uninstall. The autopilot changes nothing else on the Mac. Deleting `scripts/autopilot.sh` is optional — a script that nothing schedules never runs.
