## What I did

### 1. The scorecard model — `knowledge/scorecards/platform-scorecard-model.md`

The formula document. Per platform, per category, every metric with its weight,
its formula, its input file, and — where there is no input file — the exact export
that would create one. It also states the two rules the whole thing hangs on and
the order in which the scores actually get to 10/10.

Four scores per platform, exactly as asked:

| id | Label on screen | What it answers |
|---|---|---|
| `seo` | SEO | can a buyer find us on that platform |
| `ads` | Reklāmas | is the money we spend on traffic working |
| `listing` | Sarakstu kvalitāte | is the product page good enough to convert |
| `health` | Veselība | stock, margin, revenue, trend |

```
category score = SUM(weight_i * score_i) / 100      (weights sum to exactly 100)
platform overall = mean of the four categories
shown as x.x / 10
```

### 2. The calculator — `scripts/platform-scorecards.js` (974 lines)

Reads six real files and computes all 67 metrics. Nothing is typed in:

| Input | Used for |
|---|---|
| `data/product-master.csv` | catalogue size, per-channel presence (parsed with a real CSV reader — the file has quoted commas) |
| `data/shopify-overview.json` | Shopify catalogue, channel coverage, 30-day sales |
| `data/amazon-venues.json` | venues connected vs venues carrying listings |
| `data/product-dimensions.json` | products with a **sourced** size |
| `exchange/results/t-0003.md` | the 30-day PPC report — **parsed** out of its own tables |
| `exchange/results/t-0043.md` | the live site crawl — **parsed** out of its envelope JSON |

The two result files are parsed rather than transcribed so the scorecards cannot
drift from the reports they came from. If a report is ever reshaped, the reader
throws and the suite fails — tested four ways (see Evidence).

`node scripts/platform-scorecards.js --json` writes `data/platform-scorecards.json`;
`--js` prints the block embedded in the app.

### 3. The honesty rule — measured vs missing

Every metric is one of exactly two things:

- **`measured`** — from a real file, and `source` names it. A measured 0 is a real
  result (Shopify's Product JSON-LD count is a measured 0; so is "0 of 206
  products have a sourced size").
- **`missing`** — no data. It scores 0, because an unproven channel is not a 10/10
  channel, but it is rendered as **"nav datu"**, never as a measurement, and
  `needs` names the export that would fix it.

So every card carries **two numbers**: the score, and `measured_share`. On screen
the second one is a hatched tail on the bar. **0.0/10 at 0% measured reads "we are
blind here", not "we are bad here"** — and the note under the band says exactly that
in Latvian.

One judgement call worth flagging: the empty `etsy` column in `product-master.csv`
is recorded as **missing**, not as a measured zero. The column is empty *because
there is no connector*; an absence of data is not a measurement of zero listings.

### 4. The app — "📊 Rezultāti" on the farm main screen

Two surfaces for the same config, matching how the personas band already works:

- **HUD strip** (`#scoreHud`, `index.html:1371`) — always visible on the main
  screen: one chip per platform with its score, or "nav datu". This is the summary
  the task asked the main view to carry.
- **Card band** (`#scoreBand`, `index.html:1432`) in the panel: the gate lock, then
  one card per platform with an SVG ring for the overall and four bars for the
  sub-scores, then "▼ Rādīt, no kā tas sarēķināts" which unfolds every metric with
  its value and source file, or its "nav datu — vajag: …" line.

Both the ring and the bars are drawn in two parts: a solid arc/fill for what was
earned and a hatched arc/tail for the weight nobody measured — the same stripe
pattern the goal bar already uses for "not connected", so one visual language
means one thing across the screen.

The owner's strategy is a **computed lock**, not a slogan:

```
new_products_allowed = every category of every platform is at 100/100
```

Today it renders **🔒 Jauni produkti: VĒL NĒ — 0 no 16 veitiņām ir 10/10**.

No DB table was added. A migration cannot be applied from this node, and an
unapplied table nothing writes to would be dead scaffolding — same call t-0019
made for the system map. The config in `index.html` is the source, and a drift
test compares it with the generator.
