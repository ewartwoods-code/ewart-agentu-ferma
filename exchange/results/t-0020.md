## What I did

### 1. Fullscreen scene (`app/src/public/index.html`)

- `body` lost its padding and got `overflow:hidden` (`index.html:19-30`): the page itself never scrolls any more.
- New `.stage` (`index.html:79-101`, markup `index.html:1001-1008`) is a `position:fixed; inset:0` window with `touch-action:none`, so a touch drag pans the farm instead of scrolling the document.
- `.scene` is no longer a fixed-aspect letterbox. It is the *world*: absolutely positioned, sized in pixels by the camera, moved with `transform: translate(...) scale(...)` and `transform-origin:0 0`. Every agent keeps its percentage coordinates, so panning/zooming never touches stored data.
- A HUD (`index.html:102-160`, markup `index.html:1011-1043`) floats above the farm. `.hud` is `pointer-events:none` and only `.hud-bar` is `auto`, so a drag that starts on empty sky still pans. It carries: the live badge, the scene switcher, the event ticker, the zoom controls, the Latvian hint `🖐️ Velc, lai pārvietotu ainu · velc minjonu, lai pārvietotu viņu`, the save-state label and the control-panel link.
- Everything that used to sit under the farm (platform band + token meters, system map, subscription register, header text, footer) moved **unchanged, same ids** into a slide-in drawer `<aside class="side-panel">` (`index.html:165-185`, markup `index.html:1045+`), opened by `📋 Paneļi`. No surface was dropped.
- Mobile rules rewritten (`index.html:962-985`): the old portrait crop (`aspect-ratio: 3/4`) is gone — on a phone the world is simply wider than the screen and the owner pans sideways.

### 2. Pan and zoom (`index.html:1610-1832`)

- `worldSize()` computes the smallest world that *covers* the viewport at the scene's own aspect ratio, times `WORLD_SLACK = 1.12` so there is always somewhere to pan at 100%.
- `clampView()` guarantees the world edge may touch the viewport border but never cross it — no bare gutter is ever visible.
- `setZoom(target, cx, cy)` is anchor-preserving: whatever is under the cursor/pinch centre stays there. Range 100%–300%.
- Mouse drag, touch drag, wheel zoom (`passive:false`, so the page cannot scroll instead), two-finger pinch, `− / + / ⌖` buttons, and re-fit on `window.resize` keeping the chosen zoom.

### 3. Moving minions (`index.html:1699-1832`)

- One rule decides drag vs pan: a `pointerdown` on a character calls `stopPropagation()` and cancels any pan/pinch in flight, so the stage never sees it. A press anywhere else pans.
- A press becomes a drag only after `DRAG_THRESHOLD = 4px`; below that it is a tap and opens the profile / Herme menu exactly as the old click did. The approve button stops both `pointerdown` and `click`, so approving is unaffected.
- While carried: `.agent.dragging` (no transition, lifted, name badge highlighted), pointer captured on the stage, position clamped to 3–97 % so nobody can be thrown off the scene.
- The 15 s poll skips the redraw while a character is held (`loadAndRender`), so the farm never yanks a minion out of the owner's hand.

### 4. Four scenes (`index.html:1440-1550`, `1937-1975`)

| id | name | cast today |
|---|---|---|
| `ferma` | Galvenā ferma (default) | all 9 field characters |
| `amazon` | Amazones ēka | Herme |
| `art` | Mākslas šķūnis | Herme |
| `sistemas` | Sistēmu centrs | KODERIS + Herme |

Each scene carries `id`, Latvian `name`, `desc`, a `background` (image or painted CSS gradient) with its own aspect ratio, and a **declarative** membership rule (`rooms` + `tiers`) — never a list of agent ids. A test enforces that: no agent id may appear inside the `SCENES` block. So a minion added to the database tomorrow lands in the right room with no code change, and Herme (tier `boss`) appears in every scene. Adding a fifth room is one entry in `SCENES`.

### 5. Positions (`index.html:1546-1608`, `1834-1935`)

Resolution order per `scene_id + agent_id`:

1. row from `agent_scene_positions` (shared, database),
2. `localStorage` key `ewart_farm_positions_v1` (this browser),
3. `ferma` → the agent's own `pos_x` / `pos_y` through the existing room logic — **unchanged**, so the main farm looks exactly as it did,
4. any other scene → `fallbackPosition(index, total)`: a deterministic even grid, no per-agent coordinate hardcoded anywhere.

Saving goes local-first (instant, always works), then through the token-gated RPC when both an admin token and the table are present. The HUD label states exactly what happened and never claims a shared save that did not occur:

- `💾 N pozīcijas tikai šajā pārlūkā (datubāzes tabulas vēl nav)` ← the state today
- `💾 N pozīcijas tikai šajā pārlūkā — spied "Saglabāt datubāzē"`
- `☁️ N pozīcijas datubāzē (redzamas visur)`

`☁️ Saglabāt datubāzē` pushes the whole scene and reports `saved/total` plus the real database error if one comes back. `↺ Sākuma vietas` clears the scene's saved layout (local always, database too when the token and table exist).

### 6. Migration — created, NOT applied

`app/supabase/migrations/20260817120000_agent_scene_positions.sql`

- table `agent_scene_positions(scene_id, agent_id, pos_x, pos_y, updated_at)`, PK `(scene_id, agent_id)`, `pos_x/pos_y` bounded 0–100 by a CHECK.
- RLS enabled, **one** policy: `for select using (true)`. No insert/update/delete policy for anon — the no-public-write invariant holds.
- Two `security definer` RPCs following the existing `admin_*` pattern, both checking `app_secrets.admin_token`: `admin_set_agent_scene_position` and `admin_reset_agent_scene_positions`.
- `agents.pos_x` / `agents.pos_y` are not touched, so an unapplied migration cannot move a single character.
- Plain ASCII only (repo rule for `.sql`), and the header says in full that it was not applied.
