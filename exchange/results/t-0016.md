## What I did

### 1. Everyone stays on the field (`app/src/public/index.html:1073-1159`)

The hide is gone. `renderAgents()` used to compute
`const isOut = isBoss || !!task; if(!isOut) return;` — a minion existed on the scene
only while it held an active/review task, which is exactly why `app/README.md`
records that "the live scene right now shows Herme alone". Now every row that is not
a `platform` row is drawn on every fetch, and presence carries no meaning at all.

- An agent with **no `cutout_url`** is not dropped either: it renders a lettered
  placeholder body (`.figure-ph`, `app/src/public/index.html:253-266`, built at
  `:1124-1126`) tinted with the
  same deterministic per-agent accent the profile modal uses. A newly registered
  minion therefore has a visible anchor from its first day, before any art exists.
- Idle characters get `.agent.idle` and step back visually (slight desaturation, muted
  bubble) so the eye still lands on whoever is actually working; hovering restores them.

### 2. The dot tells the truth (`app/src/public/index.html:1088-1140`)

| State | Dot | Latvian tooltip |
|---|---|---|
| `tasks.status = 'active'` | green, pulsing (`.status-dot`) | `Strādā` |
| `tasks.status = 'review'` | amber (`.status-dot.review`) | `Gaida apstiprinājumu` |
| no active/review task | grey (`.status-dot.resting`) | `Atpūšas` |

One rule for every tier, including the boss. **This changes Herme:** he used to be
`working = isBoss ? true : ...`, i.e. permanently green whether or not anything was
happening. He is now green only while he holds an active task. That is the honest
reading of "green = actually working" from the brief — flagged as a question above in
case the owner prefers the old always-green boss.

The bubble follows the same three states: task title while working, result summary +
the approve button while in review, and — new — the agent's **own quote** from
`agent_status` while idle (falling back to `💤 Atpūšas`). `agent_status.current_task`
is deliberately **not** used on the field: it can still hold a job that ended days ago,
and showing it would imply live work. That is one extra table in the 15-second poll
(`app/src/public/index.html:1997-2006`), public-read like the rest.

### 3. Rooms — the extensible foundation (`app/src/public/index.html:969-1071`)

```
ROOMS = art "Mākslas šķūnis" | amazon "Amazones ēka" | kods "Koda darbnīca"
        + ferma "Vispārējā ferma"  (whole scene, drawn as no panel)
```

- **Grouping rule** (`roomForAgent`): an `agents.room` value wins if the column ever
  exists → otherwise plain-ASCII keyword rules over `id + name + role` → otherwise the
  default farm. Latvian diacritics are folded first (`asciiFold`), so `makslas` matches
  "Mākslas". Matching is whole-word: without that, `Stāda kartupeļus` would land in the
  art barn because "k**art**upelus" contains "art". There is a test for exactly that.
- **Positions still work** (`agentPosition`): `pos_x` / `pos_y` are read as percentages
  **of the agent's room**, and the default room is the whole scene — so every existing
  row renders at precisely the coordinate it renders at today (test:
  `86,72 -> 86,72`). A minion inside a named room is placed inside that room's rectangle.
- **Only occupied rooms are drawn** (`renderRooms`), each with its Latvian label and an
  occupant count, on a `pointer-events:none` layer behind the characters so a room panel
  can never swallow a click meant for a minion.
- **Adding a room later** = one entry in `ROOMS` + one rule in `ROOM_RULES`. Proven by a
  test that drops in a "Vizualists / Renderē attēlus" agent and watches the art barn
  appear with no code change.
- The profile modal now badges which room a minion belongs to
  (`app/src/public/index.html:1623`).

### 4. Avatars

- **KODERIS**: `app/src/public/avatars/koderis.svg` — a flat-vector coder persona
  (dark-teal hoodie, glasses, headphones, laptop showing a green terminal), clearly not
  the cowboy boss and not a farm-chore minion. **Self-hosted**, served by the app's own
  static handler at `/avatars/koderis.svg`; no fonts, no scripts, no external
  references, so it costs nothing and cannot expire. It is the first character art in
  this project that is not hot-linked to the third-party Higgsfield CDN.
- **No existing cutout was overwritten.** All 16 original CloudFront URLs are byte-identical
  (there is a test asserting the count).
- **No new art was generated.** Producing persona images for the other minions would mean
  calling a paid image service — out of bounds for `code_local`, and the brief itself says
  keep an existing real cutout. The remaining seven still carry their farm-chore art; the
  mechanism to give any of them a self-hosted persona is now one file + one `cutout_url`.
- `app/src/public/avatars/README.md` documents how to add the next one.
- The profile modal no longer breaks for an agent with no video: it used to set
  `mVideo.src = a.video_url` unconditionally (an empty value makes the browser load the
  page URL as media and error). It now falls back to the still avatar
  (`app/src/public/index.html:1552-1570`).

### 6. One security fix found while testing (`app/src/public/index.html:1161-1169`)

The XSS test written for this task failed on the first run and exposed a **real,
pre-existing hole**: `escapeHtml()` escaped `& < >` but not quotes, while its output was
being interpolated into attributes (`src="..."`, `data-...="..."`) all over the page. A
`cutout_url` of `" onerror="alert(1)` produced a live `onerror` handler. `escapeHtml()`
now also escapes `"` and `'`, which fixes every call site at once; text contexts are
unaffected (the entities render as the plain characters). Exploiting it required a write
to `agents`, which is token-gated — so this was latent, not live.
