### 2. `scripts/render-brief.js` (new, 633 lines) — the guide as working code
The guide is not a document the next agent can drift from: the hard rules are executable.

- `SCALE_REFERENCES` (`scripts/render-brief.js:44-102`) — 7 objects, each with its dimensions,
  a near/room band and a **stated source** for the number.
- `INTERIOR_LIBRARY` (`scripts/render-brief.js:111-166`) — 6 interiors, each with its own room
  build, required visible textures, light setup and allowed scale anchors.
- `pickScaleReferences()` (`scripts/render-brief.js:220`) — picks one near-field and one room
  anchor closest in log space to the product's longest side, and flags a comparison as out of
  band outside 0.15x-8x.
- `ratioLine()` (`scripts/render-brief.js:200`) — the ratio sentence: percent always, plus the
  x-form above 200%.
- `pickInteriors()` (`scripts/render-brief.js:260`) — ranks interiors by matched description
  keywords; a zero-match interior is returned marked `provisional`, never silently.
- `buildBrief()` (`scripts/render-brief.js:283`) — emits the 11 numbered blocks; when
  `dimensions_cm` is null it emits `MEASUREMENT REQUIRED`, writes no ratio, and the copy-paste
  prompt says "do not send this prompt yet".
- `buildDimensionSvg()` (`scripts/render-brief.js:431`) — FRONT / SIDE / TOP plus an **A4 sheet
  drawn at the same scale**, with dimension lines, the source of the numbers printed on the
  drawing, and XML escaping.
- `loadProducts()` (`scripts/render-brief.js:530`) — **refuses a dimension that has no
  `dimensions_source`** and refuses a non-positive dimension. A size with no source is a guess
  and the loader treats it as an error.
- CLI exit codes: `0` ready, `2` bad input / unknown SKU, `3` blocked on a missing size, so no
  automated pipeline can walk past a missing dimension.

Output is deterministic (no timestamps, no randomness) so a regenerated brief can be
byte-compared with the committed one — and the test suite does exactly that.
