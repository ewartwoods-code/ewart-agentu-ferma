### 3. Click → home scene

`openPersonaHome(id)` (`app/src/public/index.html:4374`) draws the room and fills the panel:

- **The room is drawn, not an image asset.** `personaRoomSvg()` (`:4238`) renders one SVG (viewBox `0 0 100 62`): wall, per-persona accent wall, oak floor with perspective planks, skirting board, a window with a daylight shaft, then the furniture. Furniture comes from `room.props`, a list of four typed primitives — `shelf`, `block`, `pot`, `rug` (`personaPropSvg()`, `:4199`). An unknown type draws **nothing** rather than guessing a shape.
- **Items are labelled HTML buttons** on top of the SVG (`personaSpotsHtml()`, `:4274`) — so a tap and the keyboard both work and nothing depends on hover. Clicking one fills the box below with what that item means for us. The first item is opened on load, so the box is never an empty rectangle.
- Below the room: `Viņas dzīve` (fact chips), `Kāpēc viņa pērk pie mums`, `Ko viņa grib no mums`, `No kurienes šie dati`, and chips to walk into another persona's home without closing the panel.

### 4. The faces

No persona photo asset exists in this repo, and generating one is an outward, paid image call — out of scope for `code_local`. Per the task's fallback ("tasteful monogram/illustration placeholder with a note") I drew them instead: `personaFaceSvg()` (`:4165`) renders a flat SVG portrait — background circle, hair (bob / bun / long / short, one colour per persona), shoulders, face, fringe, eyes, mouth, an earring, optional glasses — all clipped to the avatar circle. Each face gets a unique `clipPath` id, so two avatars on one page cannot clip each other (tested).

**The note is on the card, not buried in a comment** (`personaNote`, `:4340`):

> "Sejas un istabas ir zīmētas ilustrācijas, nevis īstu pircēju foto. Tirgi, cenas un preču kategorijas nāk no izmērītiem pārdošanas datiem; vecums, mājoklis, mājdzīvnieks un hobiji ir pieņēmumi no analīzes t-0031. Katrā mājā sadaļa «No kurienes šie dati» pasaka, kurš ir kurš."

### 5. Data-driven: config now, table when approved

`app/supabase/migrations/20260817180000_personas.sql` — **CREATED, NOT APPLIED** (`code_local`).

- `personas` table with `rank`, `side`, name/title/market/line/why/wants, `evidence`, and `facts` / `face` / `room` as `jsonb` — the same shape as the config.
- `evidence` is `not null` **on purpose**: a persona on screen must always state which of its claims were measured and which are assumptions. A persona without that line would let a drawing read as a fact.
- RLS enabled, public **read** only. No insert/update/delete policy — the no-public-write invariant is intact (asserted by a test).
- The page reads it through `sbGetOptional('personas?select=*&order=rank.asc')` (`:4478`), so the three states are all honest and all tested:

| State | What renders | What the source line says |
|---|---|---|
| table absent (today) | the config | "no personu analīzes t-0031 — tabula personas vēl nav izveidota" |
| table empty | the config | "tabula personas ir tukša — rāda personu analīzi t-0031" |
| table has rows | the rows, per field over the config | "no datubāzes tabulas personas — N ieraksti" |

A half-filled row inherits the missing fields from the config entry with the same id, so a partial row can never blank a persona out. A row without an `id` or `name` is dropped rather than drawn half-empty.

### 6. Security

Everything reaching an SVG attribute goes through `safeColor()` (hex-only regex) and `numOr()` / `clampTo()`; all text goes through the existing `escapeHtml()`. That matters because a future `personas` row is database text: a colour like `#fff" onload="alert(1)` would otherwise close the attribute. Tested with hostile colours, names, ids and item labels — all four assertions pass. No key, no URL, no secret in the persona block (asserted).

## Notes for Hermes

1. **Not deployed.** `app/src/` in this repo is a snapshot; the live site is `ewartwoods-code/ewart-agentu-ferma` `main` on Railway. This change reaches the owner's browser only after it lands there — that is an outward action and it is not done. 0 deploys, 0 EUR, 0 network calls.

2. **Migration not applied.** `20260817180000_personas.sql` exists as SQL only. Today the band runs off the config and says so on screen. Apply it when the owner wants to edit a persona without a code change.

3. **The faces are drawings, and I did not hide it.** The task allowed a generated persona image; producing one means calling an image model, which is an outward, paid action and outside `code_local`. The drawn SVG fallback the task named is what shipped, with a standing note on the card. If the owner wants photoreal portraits, that is a separate task with a cost estimate — say the word and I will price it before anything is spent.

4. **I could not rasterise the page in this sandbox.** `qlmanage`, ImageMagick and every headless browser were blocked, so I have not looked at a rendered pixel of the room — I will not claim "it looks good" on a screenshot I never took. Instead the layout is verified as geometry: props stay inside the viewBox, every floor-standing block's bottom edge lands on the skirting line (all 9 sit at y = 47.0–47.6 against a 46.2 line), shelves hang above it, rugs lie below it, plants do not grow through the ceiling, and no two labels in a room collide. That check found and fixed one real overlap (Maïa's "Kāpnītes pie izlietnes" and "Līdzsvara baļķis gaitenī" were 4% apart vertically and would have sat on top of each other). A human glance at the live page is still worth having.

5. **One behaviour change outside the persona feature:** `numOr()` refuses `null`, `''` and booleans instead of coercing them to `0`. It is new code used only by the persona module, so nothing existing is affected — but it is the reason a NULL coordinate in a future `personas` row falls back to the centre of the room instead of being pinned to the corner.

6. **What the personas still do not know.** The `[PRIOR]` layer (ages, homes, pets, hobbies) is unverified market knowledge, exactly as t-0031 left it. When t-0034 (order geographies) and t-0039 (review mining) land, the `evidence` line on each persona is the single place to update — the rest of the card follows automatically.
