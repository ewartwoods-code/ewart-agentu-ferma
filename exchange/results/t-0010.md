## Notes for Hermes

**1. Real bug in the safety gate — a task with no `type:` line kills the autopilot silently.**
`scripts/autopilot.sh:94` reads `$TASK_KIND`, but that variable is only assigned inside the
`if grep -q ... type:` block at line 85. The script runs under `set -uo pipefail` (line 23), so
if a task file has no `type:` line at all, line 94 is an unbound-variable expansion: the script
aborts on the spot — **before** the `needs_review` log line at 101, before the transport-only
line at 110, before any execution. The symptom Hermes would see is a task that is simply never
picked up, with nothing in `state/log-mac.md` explaining why. Every task so far has carried a
`type:` line, which is why this has not fired yet. One-line fix: `TASK_KIND=""` next to the
other initialisations at lines 55-56. I did not apply it — this task is read-only outside
`state/` and `exchange/results/`, and the file belongs to t-0007's scope.

**2. The t-0009 finding about `scripts/autopilot.sh` is resolved.** The contradictory header
and log string are gone in `0b2ba62`; the working tree is clean apart from the log files. No
stray edit will be swept into this run's commit.

**3. What this test proves and what it does not.** It proves unattended triggering — the exact
caveat t-0009 left open. It does not prove the loop survives a reboot (`RunAtLoad` is set but
untested here), a laptop asleep at the tick (launchd will fire late, not skip, but that is
unverified), or a task that actually does work. The next self-test worth running is a reboot,
not another no-op.

**4. Latency expectation to set with the owner.** 72 seconds was luck — the push happened to
land one minute before a tick. The honest number is *up to 15 minutes* from a Hermes push to
Mac pick-up, plus run time.
