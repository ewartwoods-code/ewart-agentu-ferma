### 1.2 Style-finder — a tool, not a paragraph (deliverable 2)

The owner asked the agent to **learn our style from the last 20 posts, including how
visuals are placed**. Since that must be repeatable (monthly, and after every theme
change), it is code:

`scripts/blog-style-scan.js` (734 lines) reads a corpus of our own posts and measures:

| Group | Measured |
|---|---|
| Length & rhythm | words min/p25/median/p75/max, H2 + H3 per post, words per section, paragraph avg + longest, lists |
| **Visuals** | images per post, images per 1000 words, **position of each image as % through the post**, zone histogram (hero / early / middle / late / closing), hero-open rate, caption rate, alt rate |
| Links & CTA | internal, product, product+collection, external links; closing-CTA rate with the evidence that triggered it |
| Titles & meta | title length, how-to / number / question / colon shares, meta-description presence |
| Topics | tag roll-up (top 12) |

It then derives `style_rules` — the machine contract (word band = measured p25..p75
rounded outward with a 300-word floor, H2 min, image min, required zones = zones
carrying ≥15% of images, caption/alt/hero/CTA switches at a 0.6 measured rate,
link minimums, paragraph ceiling). Thresholds follow the data: a corpus that does
not caption its images produces `caption_required: false`.

Input formats: Shopify Admin article JSON **or** saved HTML pages (`<article>` →
`<main>` → whole file), mixed freely; unparseable files are listed in `skipped`
instead of failing the run. `--limit 20` implements "the last 20" (newest-first
when dates exist). Output is deterministic — no timestamps, no randomness — so a
re-scan can be byte-compared with the committed metrics.

**The honest part:** there is no corpus in this repo and no way to fetch one here.
So the scan **exits 3 and writes nothing**:

```
$ node scripts/blog-style-scan.js --corpus data/blog-corpus --limit 20 \
    --out knowledge/blog/style-metrics.json --report knowledge/blog/style-measured.md
BLOCKED: no readable posts in data/blog-corpus (0 file(s) seen)
Nothing was written. The style guide keeps its unmeasured markers until a real corpus exists.
$ ls knowledge/blog/
interviews  (no style-metrics.json, no style-measured.md)
```

`knowledge/blog/style-guide.md` therefore separates what we **do** know from what we
**guessed**: `[BRAND]` = fixed by our own documents (persona, five woods, ≤120 cm,
markets, visual-render rules, placement budget), `[PRIOR]` = a value that must be
replaced by the scan. Its §7 lists all 7 gaps, G1 being the unread 20 posts.
`data/blog-corpus/README.md` gives three ways to fill the corpus (Shopify article
reads, the public Atom feed one-liner, browser saves).

### 1.3 The draft gate

`scripts/blog-style-check.js` (369 lines) grades a draft against the measured rules
(or the labelled prior when no metrics exist yet) and blocks on:

- front matter missing `title` / `meta_description` / `target_keyword` / `target`;
- SEO title outside 30–65 chars, meta description outside 120–160;
- body below the word floor; fewer H2 sections than measured; too few images;
- an image with no brief for the Visual Agent, or (when our style captions) no caption;
- **all images clumped in one zone**, or no lead visual when our posts open with one;
- fewer product/collection links than measured; no closing CTA;
- **quoted passages with no `interview_source:`, or a source file that does not exist**
  — the anti-fabrication rule;
- Latvian diacritics (repo files stay English).

Warnings (not blockers): over-long body, over-long paragraph, missing alt line, thin
internal linking, leftover `TODO`. Every run prints whether it graded against
measured rules or the prior, so a prior can never be passed off as a measurement.

### 1.4 Interview flow via WhatsApp (deliverable 3)

`knowledge/blog/interview-flow.md` — the 11-step loop: writer picks a topic → 5–8
questions → **Hermes sends them as Latvian voice notes** → owner/team answer by
voice → Hermes STT (lv) + translation → transcript at
`knowledge/blog/interviews/YYYY-MM-DD-<topic>.md` → writer maps answers to sections
→ style check → owner OK → publish. Rules encoded: a quote needs a `status: real`
transcript, Latvian voice in / English file out, the writer never sends anything,
partial answers become a documented Gaps table (never filler), named people need
consent. It also carries the answer→section mapping table (surprising fact → intro
hook, "what we refuse to rush" → the trust section, wood comparison → bullet list…).

`knowledge/blog/interview-questions.md` — 64 questions in 8 banks: team, craft,
materials, product story, room how-to, kids/Montessori, gifting, brand.

### 2.4 Two real bugs the tests caught (fixed, then re-proven)

1. **Punctuation counted as a word.** Stripping an inline tag left the following
   period as its own token (`shelf</a>.` → `shelf` + `.`), inflating every word
   count and therefore the word band. Fixed in both scripts: a word must contain a
   letter or digit (`scripts/blog-style-scan.js` `countWords`,
   `scripts/blog-style-check.js` `countWords`).
2. **The measured band could invert.** Rounding p25/p75 to the nearest 50 could push
   `words_min` above the corpus median for a short-post corpus. Fixed by rounding
   the band outward (`Math.floor` for the floor, `Math.ceil` for the ceiling), with
   the 300-word business floor kept and asserted.
   A third inconsistency was also removed: the scanner derived `product_links_min`
   from `/products/` links only while the checker counted `/products/` **and**
   `/collections/`; the scanner now measures the same "commercial links" set
   (`links_commercial`).
