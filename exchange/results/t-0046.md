# t-0046 — 2 parallel autopilot workers

## The task's premise was wrong

The task states that 2-worker parallelism was "already implemented" and
"verified on Linux: 3 workers -> 0018/0019/0020 distinct". On the code as
pushed, that cannot have happened with `scripts/autopilot.sh` as the worker
body. `autopilot.sh` took a **single lock per repo** (`state/autopilot.lock`)
before doing anything else, so the second worker in the same tick always found
worker 1's lock and exited with:

```
autopilot: another run holds .../state/autopilot.lock (pid NNNN) - skipping this tick
```

Reproduced verbatim in a sandbox before any change: `farm-workers.sh 2` started
two workers, and exactly one task was executed. The reservation system underneath
it was fine — it never got the chance to matter.

## Fix

The lock's real purpose is to stop **one worker slot** overlapping itself when a
tick outlives the 15-minute interval; that is a per-worker property, not a
per-repo one. It is now `state/autopilot.lock.<worker>`. (The repo's `.gitignore`
already anticipated this with a `state/autopilot.lock.*` line.)

Cross-worker safety does not come from that lock and never did:

- **distinct tasks** — `af_reserve_next_task` claims `state/reservations/<num>`
  with an atomic `mkdir`; the loser scans on to the next task;
- **git** — `git pull` was moved inside the same mutex that already serialised
  commit+push, so two workers cannot race on `.git/index.lock`.

Reservations also now expire (dead owner pid / no pid past a grace window /
120-minute TTL), so a worker killed mid-run no longer freezes its task forever —
see t-0045 for the full list.

## Proof

Throwaway harness: bare origin + clone + a stub `claude` that writes the result
envelope for whichever task id it is handed.

```
tick 1: farm-worker 1 started (pid 39)
        farm-worker 2 started (pid 40)
        autopilot[w-2]: found t-0001
        autopilot[w-1]: found t-0002
tick 2: autopilot[w-2]: found t-0003
        autopilot[w-1]: found t-0004
        pending tasks: 0
```

All four results were written, committed and pushed to the bare origin; no
reservation, run lock or push lock was left behind. `scripts/test-autopilot.sh`
is at 33 checks, 0 failures.

## Why it is not switched on here

`exchange/secret/BRINGUP-INSTUKCIJA.txt` (Hermes, 2026-08-17, machine-specific
and newer than this task) assigns this MacBook the single identity
`WORKER_ID=secret` running `scripts/autopilot.sh`, and
`scripts/secret-worker/setup-secret.sh` installs exactly that. Two instructions
therefore disagree about this machine. The newer, machine-specific one was
followed, and the generic `com.ewartwoods.farm-autopilot` agent that had been
installed earlier in this session was removed so only one agent ticks here.

Turning 2 workers on is now a one-line plist change, and the code behind it is
correct and tested — but it is Hermes's call, and it has a real cost: both
workers share this machine's single Claude subscription and its one Amazon
browser profile.
