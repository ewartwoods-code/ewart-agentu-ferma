## What I did

Attempted one read-only call per integration, in the order the task specified. Every
call was refused before it left the machine. Rather than report that as twelve
identical failures, I traced why, and then reported the layer that *can* still be
verified without making a call.

Three layers exist, and they fail differently. Keeping them apart is the whole point
of this report:

1. **Transport / registration** — is the connector present in this session and does its
   handshake complete? Verifiable now, from the session's own server list.
2. **Authorization** — is there a valid token behind it? Partly verifiable now: the
   runtime separates "connected" from "requires authentication".
3. **Live data** — does a real call return real account data? **Not verifiable in this
   run at all.**

t-0002 (this morning, interactive session) proved layer 3 for 13 integrations. This run
can only refresh layers 1–2. I have not restated t-0002's results as if they were
re-verified today.

### 3. eRank reachability

**No eRank connector exists on this Mac, and no eRank credentials exist in this repo.**
Keyword positions cannot be pulled today by any path.

What I could not do this run: confirm from eRank's own site whether a public developer
API exists. `WebFetch` to erank.com was refused by the same permission gate. I am not
going to assert "eRank has no API" as a verified fact when I could not check — the honest
statement is that **no eRank integration is configured here, and whether an official API
is even available is unverified.**

That leaves two routes, and Hermes should plan for the second until the first is disproven:

- **Route A — official API.** Unknown. Someone must check eRank's developer docs and the
  owner's plan tier. Cheap to settle: one web fetch from an interactive session.
- **Route B — browser session.** eRank is a paid, login-gated tool. Its Keyword Tool and
  rank-tracking views are behind that login, so a scraper needs an authenticated browser
  session driven on this Mac, plus whatever CSV export eRank offers. This is the route the
  repo already anticipates: `AGENTS.md:81` describes an agent that "operates web pages that
  have no API (e.g. Etsy admin panels)". Two constraints Hermes must weigh before
  commissioning it: eRank's terms of service may prohibit automated access, and a scraper
  needs the owner's live login — which means storing or driving a real credential.

Recommendation: settle Route A first. Do not build a scraper against an unverified
assumption.
